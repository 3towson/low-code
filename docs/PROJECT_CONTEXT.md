# Project Context: COD Customer Check

## เป้าหมาย
แอปสำหรับร้านค้าออนไลน์รายย่อย ใช้ตรวจสอบว่าลูกค้า COD มีประวัติปฏิเสธรับสินค้าหรือไม่ และใช้รายงานลูกค้าที่มีปัญหา

## ขอบเขต (ห้ามเพิ่มฟีเจอร์นอกเหนือจากนี้)
1. Login/Signup ร้านค้า (Supabase Auth, บังคับยืนยันอีเมล)
2. ตรวจสอบลูกค้า: วางข้อความออเดอร์ → แยกชื่อและเบอร์ → แสดงระดับความเสี่ยงและคำแนะนำ
3. รายงานลูกค้า: ฟอร์มกรอก ชื่อ เบอร์ แพลตฟอร์ม เหตุผล มูลค่าความเสียหาย

## Tech stack
- Flutter (Dart 3+, Material 3) อยู่ในโฟลเดอร์ app/
- Supabase Cloud (Postgres, Auth, Edge Functions แบบ TypeScript/Deno) อยู่ในโฟลเดอร์ supabase/
- Gemini API เรียกจาก Edge Function เท่านั้น ชื่อโมเดลอ่านจาก env GEMINI_MODEL
- ไม่ใช้ Supabase local stack หรือ Docker ให้ deploy ขึ้น Supabase Cloud project สำหรับพัฒนาโดยตรง
- สคริปต์ทดสอบเขียนด้วย Deno อยู่ในโฟลเดอร์ scripts/ และอ่านค่าจากไฟล์ .env

## กฎความปลอดภัย (ห้ามละเมิดเด็ดขาด)
- ห้ามเขียน API key, secret, service role key หรือรหัสผ่านลงในโค้ด ให้ใช้ Supabase secrets และไฟล์ .env ที่อยู่ใน .gitignore
- ห้ามพิมพ์ค่า key หรือ secret ออกมาใน log หรือผลทดสอบ
- การ normalize และ hash เบอร์โทร (HMAC-SHA256 ด้วย PHONE_HASH_SECRET) ทำใน Edge Function เท่านั้น ห้ามทำใน Flutter
- ห้ามเก็บเบอร์โทรจริงลงฐานข้อมูล เก็บเฉพาะ phone_hash
- Flutter ห้าม query ตาราง cod_reports โดยตรง ต้องผ่าน Edge Function เท่านั้น
- ผลการตรวจสอบห้ามเปิดเผยว่าร้านไหนเป็นผู้รายงาน ห้ามส่งชื่อลูกค้าที่ร้านอื่นกรอก และห้ามส่ง hash กลับไป

## กฎ normalize เบอร์โทร
1. แปลงเลขไทย ๐-๙ เป็น 0-9
2. ตัดทุกตัวอักษรที่ไม่ใช่ตัวเลขทิ้ง
3. ถ้าขึ้นต้นด้วย 66 และยาว 11 หลัก ให้แทน 66 ด้วย 0
4. ผลลัพธ์ต้องตรงกับ ^0[689]\d{8}$ ถ้าไม่ตรงถือว่าไม่ใช่เบอร์มือถือไทย (คืนค่า null)

## ระดับความเสี่ยง
- "รายงานที่นับ" คือรายงานที่ status = 'active' และ created_at อยู่ภายใน 12 เดือน
- "รายงานเกณฑ์แดง" คือรายงานที่นับ ที่อยู่ภายใน 90 วัน และร้านที่รายงานมีอายุบัญชีอย่างน้อย 7 วัน ณ วันที่รายงาน (report.created_at - seller.created_at >= 7 วัน)
- red: มีรายงานเกณฑ์แดงจากร้านต่างกันตั้งแต่ 2 ร้านขึ้นไป
- yellow: มีรายงานที่นับอย่างน้อย 1 รายงาน แต่ไม่ถึงเกณฑ์ red
- green: ไม่มีรายงานที่นับ

คำแนะนำที่แสดงผล
- green: "ส่งได้ตามปกติ"
- yellow: "ควรโทรหรือทักยืนยันออเดอร์กับลูกค้าก่อนแพ็กสินค้า"
- red: "ไม่แนะนำให้ส่งแบบเก็บเงินปลายทาง ควรให้ลูกค้าโอนชำระก่อน"

## ค่าที่อนุญาต
- platform: shopee, lazada, facebook, line, tiktok, other
- reason: refused_delivery (ปฏิเสธรับสินค้า), unreachable (ติดต่อไม่ได้), fake_address (ที่อยู่ปลอมหรือผิด), other (อื่นๆ)
- status: active, disputed, resolved

## วิธีทำงาน
- ทำเฉพาะส่วนที่ระบุใน prompt ห้ามแก้ไขส่วนที่ผ่านการทดสอบแล้วโดยไม่แจ้งก่อน
- ทุกส่วนต้องเขียนการทดสอบตามที่ระบุ และรันทดสอบจริง
- เมื่อจบงาน ให้รายงานเป็นตาราง: เคสทดสอบ | ผลที่คาด | ผลจริง | ผ่าน/ไม่ผ่าน
- ขั้นตอนที่ฉันต้องทำเอง (ตั้งค่า secret, กดใน dashboard, กรอก .env) ให้บอกคำสั่งหรือขั้นตอนให้ชัดเจน แล้วหยุดรอ
- ข้อความที่ผู้ใช้เห็นใน UI และ error message เป็นภาษาไทย
- เมื่อทำส่วนนี้เสร็จ ให้หยุด ห้ามเริ่มส่วนถัดไปเอง
